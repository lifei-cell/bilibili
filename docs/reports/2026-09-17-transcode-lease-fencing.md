# 转码数据库租约与代次保护

## 改动

- Flyway V6 为 `video_transcode_task` 增加 `claim_generation`、`claim_token`、`lease_until`。每次投递以原代次做条件更新，原子递增代次并生成新令牌；消息携带该代次和令牌。
- Worker 只能凭有效租约从“已投递”进入“处理中”。FFmpeg 执行期间定期续租；上传 HLS 前、每个对象上传前和结果写库前再次校验租约。
- 低清晰度先发布及最终结果都用任务 ID、代次、令牌、租约截止时间做数据库条件更新。任务结果与视频播放地址仍在同一事务内；只有最终结果清除持有令牌。失败及降级完成也受相同条件限制。
- 每次尝试将 HLS 写入 `play/<文件标识>/attempt-<代次>-<令牌>/`。旧 Worker 即使在失租后完成在途上传，也无法覆盖新 Worker 的对象；其数据库更新命中 0 行。
- 已投递或处理中的历史任务在升级时若无租约，可由发布器重新领取。旧格式消息缺少代次和令牌，会被消费端忽略。

## 验证

`mvn -s .mvn/settings.xml --batch-mode --no-transfer-progress -pl bilibili-video-service -am verify` 于 2026-09-17 通过：视频服务 30 个单元测试、1 个 H2 事务集成测试，JaCoCo 门禁通过。

H2 上使用实际 MyBatis Mapper 模拟租约到期与新 Worker 接管：旧代次的续租、完成、失败和降级更新均命中 0 行；新代次先发布低清晰度再完成后，状态与产物地址指向新结果。MinIO 客户端测试验证两个尝试的对象键不相交，失租检查阻止继续上传。事务集成测试还验证旧结果无法覆盖新播放地址。

## 边界

真实 MySQL、RocketMQ、MinIO、FFmpeg 双 Worker 崩溃接管已通过，证据见 `docs/reports/2026-09-17-p1-reliability-drill.md`。本次演练验证了领取者强制退出后新代次接管、旧产物前缀隔离和可播放 HLS；未覆盖远端或生产环境。低清晰度发布后任务处于可播放成功态；若后续档位超时，保留低清晰度结果，过期持有者无法再更新，但高档位需要独立补偿机制。孤立尝试前缀的定期清理也需后续运维任务处理。
