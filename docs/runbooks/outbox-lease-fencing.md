# Outbox 领取租约

每次领取生成独立的 `claim_token`，以数据库时间设置 `locked_until`。只有状态仍为 `PROCESSING`、令牌一致且租约未到期的执行者可以回写成功或失败；回写失败不累计成功/失败完成指标。并发领取通过同一行条件 UPDATE 竞争，旧实例暂停后恢复不能覆盖接管者状态。

V10 为增量迁移；已有 `PUBLISHED` 记录不变，旧 `PROCESSING` 记录按原 `locked_at` 超时回收。上线时先停止旧版本 Outbox 发布实例，再迁移并启动新版本，避免旧代码不带令牌的 UPDATE 绕过隔离。数据库迁移不可通过删除 V10 回退；需要回退时应停止所有发布实例并评估恢复流程。

这保证的是数据库状态回写隔离。MQ 发送与数据库提交仍不处于同一事务：发送成功但租约过期、进程崩溃或确认丢失仍可能重复投递，消费者必须继续使用 Inbox 幂等。领取超时默认 60 秒，发送超时 3 秒；不要把租约设置得短于正常发送和数据库回写所需时间。

验证：`OutboxLeaseMySqlIT` 使用真实 MySQL，覆盖双实例竞争、旧执行者暂停与恢复、租约自然失效后的回写拒绝、失败退避与次数上限、V9 到 V10 升级兼容；`OutboxEventPublisherTest` 验证成功/失败分支传递领取身份且只统计被数据库接受的回写。
